# J.Lash — сайт салона наращивания ресниц (Есик, Алматинская область)

Next.js (App Router) + TypeScript + Tailwind CSS. Все страницы пререндерены
статически, весь контент и SEO-разметка отдаются в HTML без выполнения JS.

## Команды

```bash
npm run dev        # локальная разработка
npm run build      # прод-сборка (пререндер всех страниц)
npm start          # запуск собранного сайта
npm run typecheck  # проверка типов
```

## i18n

Локали: `/ru/...` и `/kk/...`. Сегменты URL одинаковые для обоих языков —
так hreflang-пары совпадают один-к-одному и не появляется дублей.
Переводы UI и SEO-тексты: `src/content/dictionary.ts`.

- `hreflang` (`ru`, `kk`, `x-default`) выводится на каждой странице и в sitemap.
- `<html lang>` = `ru-KZ` / `kk-KZ`.
- `x-default` указывает на русскую версию.
- Редирект `/` → `/ru` — постоянный (308) на уровне `next.config.ts`.

## SEO

- Уникальные `title` / `description` / `keywords` на каждую страницу и локаль
  (город Есик, Алматинская область).
- Canonical + Open Graph + Twitter Card через Next.js Metadata API,
  сборка — в `src/lib/seo.ts`.
- JSON-LD: `BeautySalon` (в корневом layout), `BreadcrumbList`, `Service`,
  `BlogPosting` — `src/lib/jsonld.ts`.
- Формы онлайн-записи нет: связь через WhatsApp / Telegram / телефон,
  ссылки с предзаполненным текстом сообщения.

## Первый экран главной

Фон первого экрана — аналог [Ballpit](https://reactbits.dev/backgrounds/ballpit),
написанный вручную: `src/components/Ballpit.tsx`, обычный 2D-canvas без
three.js и rapier.

Что воспроизведено: пастельные сферы дрейфуют, отскакивают от границ блока,
сталкиваются друг с другом и мягко тянутся за курсором; объём рисуется
радиальным градиентом, «глубина» шарика влияет на размер и скорость.

Учтено при реализации:

- **SEO** — фон декоративный (`aria-hidden`, не влияет на разметку),
  `h1`, абзацы и CTA остаются серверным HTML;
- **`prefers-reduced-motion`** — рисуется один статичный кадр, анимации нет;
- **производительность** — спрайты шариков prerender-ятся один раз, анимация
  останавливается, когда блок вне экрана или вкладка неактивна; поток
  курсора читается пассивно, клики по кнопкам не перехватываются;
- **контраст** — поверх canvas идёт градиентная вуаль, текст читается.

Настройки (`count`, `colors`, `minRadius`/`maxRadius`, `friction`,
`maxVelocity`, `cursorStrength`) передаются пропсами из `src/app/[locale]/page.tsx`.
Если нужен точный оригинал с настоящим 3D-светом — вместо canvas
подключаем three + @react-three/fiber + @react-three/rapier.

## Логотип с эффектом «жидкий металл»

`src/components/MetallicLogo.tsx` — порт компонента
[MetallicPaint](https://reactbits.dev/animations/metallic-paint) с reactbits.dev
(автор David Haz, лицензия MIT). Шейдер скопирован дословно, GLSL-строка
не форматирована — любая «косметическая» правка там ломает картинку.

Как это работает: по альфа-каналу картинки строится силуэт, внутри силуэта
решается уравнение диффузии (SOR, 200 итераций) — получается карта
толщины фигуры. Дальше WebGL2 рисует по ней жидкий металл: полосы отблеска,
френель, хроматическое расщепление, контур и волновое искажение.

Что изменено относительно оригинала:

- **пропорции.** Оригинальный `fA()` масштабирует картинку по принципу
  «cover» — если пропорции канваса и картинки не совпадают, края обрежутся.
  Компонент читает пропорции из самого файла и ставит их контейнеру,
  поэтому логотип вписывается 1:1 без обрезки. Высоту контейнера задавать
  не нужно — достаточно ширины;
- **размер карты высот** ограничен пропсом `maxSize` (по умолчанию 768):
  решатель диффузии на 1000 px из оригинала заметно подвешивает загрузку;
- **анимация встаёт**, когда блок вне экрана или вкладка неактивна;
- **`prefers-reduced-motion`** — один статичный кадр вместо петли;
- **запасной вариант** — если WebGL2 недоступен или шейдер не собрался,
  показывается обычный `<img>` с той же картинкой;
- убраны мусорные `console.error` из оригинальной реализации.

Подпись для скринридеров задаётся через `role="img"` + `aria-label`,
сам канвас помечен `aria-hidden`.

**TODO по производительности:** эффект грузит `public/Logo.png` целиком —
это 345 КБ и 3508×2480. Перед запуском стоит отдать уменьшенный логотип
(достаточно ~1000 px по длинной стороне).

## Сетка услуг (Magic Bento)

`src/components/MagicBento.tsx` — порт компонента
[MagicBento](https://reactbits.dev/components/magic-bento) с reactbits.dev
(автор David Haz, лицензия MIT). Используется в блоке «Услуги и цены»
на главной и на странице `/uslugi`. Стили — в `globals.css`, блок
«Magic Bento».

Эффекты: спотлайт по секции, следящий за курсором, подсветка рамки карточки
в точке курсора, искры при наведении, притяжение карточки к курсору (магнетизм),
волна света от клика.

Что изменено относительно оригинала:

- **анимации на CSS и rAF вместо GSAP** — библиотека не тянется ради трёх
  эффектов;
- **сетка 3×N с крупной первой ячейкой 2×2** вместо жёстких `nth-child`
  из оригинала. Такая раскладка закрывает строки без дырок и для 6 карточек
  (главная), и для 9 (`/uslugi`);
- **карточки — настоящие ссылки** на страницы услуг: `<a>` с текстом
  заголовка индексируется, а прозрачный `::after` лишь растягивает область
  клика. Внутренняя перелинковка не страдает;
- **палитра под бренд** — глубокий сливовый вместо чёрного, пудрово-розовое
  свечение вместо фиолетового. Меняется одной переменной
  `--bento-glow` в `globals.css`;
- **уважение к `prefers-reduced-motion`** — в оригинале только проверка ширины
  экрана; эффекты отключаются на мобильных и при reduce-настройке;
- **позиции карточек кэшируются**: оригинал читал `getBoundingClientRect`
  каждой карточки на каждое движение курсора, здесь — одно чтение на кадр,
  остальное берётся из кэша;
- уровень заголовка карточек задаётся пропсом `headingLevel` — на главной это
  `h3` (над сеткой есть `h2`), на `/uslugi` — `h2`.

Группировка услуг по категориям сохранилась: категория выведена в подписи
в углу каждой карточки, поэтому отдельные подзаголовки-разделы больше
не нужны.

## Кнопки (Star Border)

`src/components/StarBorder.tsx` — порт компонента
[StarBorder](https://reactbits.dev/animations/star-border) с reactbits.dev
(автор David Haz, лицензия MIT). Стили — в `globals.css`.

Как это работает: контейнер с `overflow: hidden` и вертикальным паддингом
в `thickness` пикселей; под непрозрачной «шляпкой» кнопки ходят два широких
радиальных градиента. Видна только тонкая полоса по верхней и нижней кромке —
по ней и пробегает блик.

Где применяется: главная кнопка в блоке связи с клиентом (одна на блок —
анимировать все четыре означает превратить акцент в шум) и кнопка отправки
отзыва. Остальные кнопки остались плоскими.

Отличия от оригинала (осознанные):

- **у контейнера есть свой фон**. В оригинале полоса под бликом прозрачная,
  и сквозь неё видно фон страницы. На тёмной демке это работает, а на светлой
  кремовой странице светлый блик оказывался *темнее* окружения и почти
  не читался. Теперь полоса залита цветом кнопки, и блик идёт по ней;
- **цвета — через CSS-переменные**, а не инлайновый `background`: иначе
  нельзя было бы сделать состояние наведения;
- **`prefers-reduced-motion`** — анимация отключается (проверено);
- **`focus-visible`** — кнопка остаётся видимой при навигации с клавиатуры;
- `<a>` не принимает `disabled`, а `<button>` — `href`, поэтому ссылка
  и кнопка рендерятся разными ветками, а не «полиморфно».

Блик настраивается: `color` (цвет звезды), `speed` (длительность прохода),
`thickness` (толщина полосы), `backgroundColor` / `hoverBackgroundColor`.

Сейчас в `public/` лежат `Logo.png` и `favicon.ico` размером 3508×2480

## Отзывы

`POST /api/reviews` → валидация (имя 2–60, текст 20–1200, оценка 1–5) +
honeypot-поле → отзыв попадает в очередь на модерацию.
Опубликованные отзывы лежат в `src/data/reviews.json`.

**Временное хранилище:** новые отзывы пишутся в `data/pending-reviews.json`
(в `.gitignore`). Это работает локально, но **не работает на Netlify** —
файловая система функции доступна только для чтения, и там форма вернёт
503 с предложением написать в WhatsApp.

Перед деплоем нужно подключить внешнее хранилище: заменить тело
`getReviews` и `submitReview` в `src/lib/reviews.ts` на вызовы
выбранного сервиса (Supabase / Airtable / Netlify Blobs). Интерфейс,
валидация и API-роут менять не придётся.

## После деплоя

1. Зарегистрировать сайт в Яндекс.Вебмастере и Google Search Console,
   вставить коды в `site.verification`.
2. Проверить `/robots.txt` и `/sitemap.xml` на реальном домене.
3. Создать профили в Яндекс.Бизнесе и 2ГИС с теми же названием, адресом
   и телефоном, что в `src/lib/site.ts`.
4. Подключить домен и заменить `site.url` (домен попадёт в canonical,
   OG-теги и sitemap).
